# 실험 품질 규칙

적용일: 2026-10-17. 출처: 자매 리포 [roboco-io/coding-agent-benchmark](https://github.com/roboco-io/coding-agent-benchmark/blob/main/docs/experiment-quality-rules.md)의 품질 규칙(2026-09-19 제정, 2026-10-10 개정)을 이 리포의 비교 축(구현 언어)에 맞게 옮겼다. 원문에서 근거로 인용한 EXP 번호는 자매 리포의 실험이다.

실험을 관리하는 에이전트가 설계·실행·계측·분석·보고에 적용한다. 단순 번역이나 일반 문서 편집에 새 실험을 요구하지 않는다. 현재 요청 범위 안에서 적용하며, 미측정·미적용 항목은 이유를 기록한다.

## 우선 목표 — 바이브 코딩 백엔드 언어 선택 (2026-10-17 사용자 확정)

- 이 리포의 기본 질문은 "바이브 코딩으로 백엔드를 만들 때 어떤 언어가 가장 적합한가"다. 모델·하네스(Claude Code + Sonnet 5.5 / Opus 5.5)와 과제(RealWorld 백엔드)를 고정하고 구현 언어(TypeScript, Python, Go, Rust, C++)를 바꿔 비교한다.
- 측정 대상은 "에이전트가 만든 코드"다. 언어 런타임 자체의 순수 성능이 아니므로, 결과는 언어와 에이전트 구현 선택이 섞인 값으로 해석한다.
- 선택 근거는 만드는 과정 지표(구현 속도, 실패 포함 비용, 반복 횟수, 사람 개입, 구현 안정성)와 결과물 지표(런타임 속도, 메모리, 런타임 안정성, 코드량·의존성, 빌드·배포, 보안, 유지보수성)다. 정의는 [과제 README](../tasks/realworld-backend/README.md)와 [지표 스키마](../analysis/metrics/SCHEMA.md)를 따른다.
- 언어 간 측정 조건(리소스 제한, 부하 시나리오, 채점 정본, 워커 규칙)이 다르면 비교가 성립하지 않는다. 조건이 달라진 run은 비교에서 분리해 표시한다.

## 1. 자매 리포 계측 오류 — 기준선을 인용할 때 확인

- 자매 리포 결과(예: EXP-026 Opus 5.5, EXP-031 Sonnet 5.5의 TypeScript run)를 기준선으로 인용할 때는 자매 리포의 [정정 기록](https://github.com/roboco-io/coding-agent-benchmark/blob/main/docs/2026-09-21-corrections.md)을 확인한다.
- 자매 리포의 TS run은 앱 코드가 보존되지 않아 결과물 지표가 없다. 이 리포의 TS 결과는 새 하네스로 다시 측정한 값이며, 자매 리포 값은 재현 확인용 기준선으로만 쓴다.
- 자매 리포의 합격 조건은 호스트 채점만이고, 이 리포는 호스트(`start.sh`)와 Docker 이미지 양쪽 채점이다. 구현 시간을 비교할 때는 "호스트 채점 통과 시점"만 맞춰 비교한다.

## 2. 실행 전 — 질문·비교 조건·예산 고정

- 질문을 **완주 가능성 / 실무 조합 효율 / 요인 효과 분리** 중 무엇으로 답할지 명시한다. 완주 실험을 사후에 효율 우위 실험으로 바꾸지 않는다.
- 모델 ID·가능한 리비전·추론 설정, 실행 도구·버전, 작업 전략, 제공자·연결 계층을 별도 항목으로 적는다. 함께 달라진 요소가 있으면 전체 조합의 차이로 해석한다.
- 원인 분리에서는 비교할 요인 외 조건을 맞춘다. 모델×도구 상호작용을 주장하려면 필요한 교차 조합을 관측한다. 지원하지 않는 조합은 미관측으로 남긴다.
- 과제·초기 저장소 커밋, 프롬프트·채점 정본의 버전/해시, 완료 기준을 조건 간 고정한다. Hurl과 Newman 등 다른 테스트 세트를 같은 품질의 증거로 취급하지 않는다. 커밋 수·코드량·문서량은 품질로 단정하지 않는다.
- 환경 기록에 OS·런타임·CLI·채점기 버전, 실제 노출된 글로벌 지침·스킬·MCP·권한·격리 방식·캐시 조건을 포함한다. 인증정보는 제외한다. 원문을 보관할 수 없는 설정은 해시와 확보 한계를 남긴다.
- 같은 과제와 가까운 실행 시점을 묶어 조건 순서를 무작위화하거나 균형 있게 교차한다. 과거 결과와 비교할 때 시점·설정·CLI 차이를 명시한다. 강한 효율·원인 주장이 필요하면 동시기 기준선을 다시 측정한다.
- 과제 수와 과제별 반복 수를 구분한다. 반복 수의 근거, 주 지표, 실무적으로 의미 있는 차이, 분석 방법, 제외·재실행·중단 규칙을 실행 전에 정한다. 작은 파일럿은 탐색으로 표시한다.
- 시간 상한·iteration 상한, 측정 가능한 비용 상한 또는 구독 한도 대응을 정한다. iteration 수만으로 자원 예산이 같다고 주장하지 않는다. 무개입·허용 개입 범위도 정한다.
- **실행 전 모델 입력 한도·과금 체계를 확인하고 사용자에게 진행 여부를 묻는다 (2026-10-10 사용자 지시).** 조건별 입력 컨텍스트 한도·최대 출력·단가(입력 길이 구간 포함)·구독 여부를 출처·확인일과 함께 기록하고, 이 과제의 토큰 프로파일(과거 완주 run 최대 프롬프트 p90 153K·최대 174K, run당 총 입력 p50 2.2M·p90 8.3M)과 비교한 적합성·추정 비용 보고서를 사용자에게 보여 준 뒤 승인받는다. 입력 한도 200K 미만은 부적합, 256K 미만은 주의로 표시한다. 근거: EXP-042 coder(204,800)·EXP-043 gpt-oss(약 128K)는 이 과제와 상성이 나빴다.
- **API 과금 실험은 실행 중 강제되는 비용 상한이 필수다 (2026-10-10, EXP-042 재발 방지).** 설계 문서에 공개 단가(출처·확인일, 입력 길이 구간 단가 포함), run당 상한(`RUN_BUDGET_USD`), 실험 상한(`EXP_BUDGET_USD`)과 최악의 경우 총액(run당 상한 × run 수)을 사전 등록하고 사용자 승인을 받는다. 하네스는 30초마다 추정 비용을 확인해 상한에 닿으면 진행 중 iteration을 종료하고 남은 run을 시작하지 않는다. 사후 집계로만 확인하는 비용 상한은 상한이 아니다. 근거: EXP-042는 "환산 $20 초과 시 중단 검토(사후 집계)"만 두어 qwen3-coder-next 2 run이 약 $92, 실험 전체가 청구액 $94.22가 됐다.
- run 시간 상한 기본값은 20분, 정체 한도는 300초다(2026-10-10 사용자 지시). 더 긴 상한이 필요하면 근거와 최악 비용을 설계 문서에 쓰고 사용자 승인을 받는다.

## 3. Phase 0·실행 — 채점과 사용량을 먼저 확인

- **비용 계측이 정확한지 Phase 0에서 확인한다 (2026-10-10).** `claude-direct`는 smoke.sh가 tool_result 약 6천 토큰을 넣은 요청으로 제공자의 입력 usage 보고를 검사하고, 기대치의 50% 미만이면 기동을 막는다(`usage_probe.py`). Claude Code는 이 보고값으로 자동 압축을 시작하므로 누락되면 컨텍스트가 입력 한도까지 커지고 비용이 급증한다(EXP-042 D-1: DashScope Anthropic 호환 엔드포인트가 36으로 보고).
- **실행 중 이상 징후를 보면 먼저 실험을 멈추고 사용자에게 알린다.** 같은 API 오류(입력 한도 초과 400 등)가 iteration마다 반복되거나 run 시간이 최근 완주 범위를 크게 넘으면, 원인 조사는 실험을 멈춘 뒤에 한다. 실행 중에 조사하면 그동안 과금이 계속된다(EXP-042: 400 반복을 확인한 뒤 원인 조사가 끝날 때까지 coder-en-2가 71분 실행됨).

- 제공자 스모크와 usage 확인을 수행한다. 에이전트의 완료 선언과 별도로 고정한 채점기로 실제 산출물을 판정한다.
- 채점기 변경이나 새 환경에서는 알려진 정상·오류 사례로 채점을 확인한다. 채점 파일 존재·해시, 채점기 실행 경로·버전, 종료 상태와 예상 테스트 수를 확인하여 빈 테스트나 잘못된 바이너리로 통과하지 않게 한다.
- 채점기 바이너리는 절대 경로로 고정하고 Phase 0에 버전 출력을 기록한다. 이 리포의 `hurl`은 Orange Hurl(`/opt/homebrew/bin/hurl`)만 뜻하며, PATH에 먼저 잡히는 npm `@hurl/cli`(버전 `1.0.0`)는 같은 이름의 다른 도구라 채점에 쓰지 않는다 (EXP-020 오검, [CLAUDE.md](../CLAUDE.md) 환경 주의).
- 서버 포트를 고정하지 않는다. 하네스는 실행·채점마다 빈 포트를 찾아 `PORT`로 주입하고, 채점 요청은 실험 대상 리포 소속 프로세스가 실제로 LISTEN한 포트로만 보낸다. 외부 프로세스가 점유한 포트(예: VS Code 확장의 3000번)를 피하려고 그 프로세스를 종료하지 않는다 (2026-10-10 사용자 지시, 근거: EXP-029 D-1 거짓 음성, EXP-031 빈 포트 주입).
- 채점 정본은 실험 대상이 수정할 수 없는 위치에 보관한다. 일반화·품질 주장이 목적이면 조정용 과제와 최종 평가 과제를 구분한다. 숨긴 테스트는 명세에 있는 동작을 검사한다.
- run마다 초기 코드·DB·세션을 초기화한다. 통제할 수 없는 서버 캐시나 공유 한도는 상태와 한계를 기록한다.
- 원자료, run/요청 식별자, 시작·종료 시각, 종료 코드, 채점 결과, 산출물 커밋, 개입·장애를 보관한다. 재시도·재채점은 이전 기록을 덮어쓰지 않는다.
- 실패는 모델/산출물, 실행 도구·변환 계층, 제공자, 채점기, 사람 개입으로 구분한다. 불분명한 원인은 추정으로 표시하고, 정한 제외 규칙과 다른 처리는 이탈로 기록한다.

## 4. 집계 — 메시지 행과 API 요청을 구분

- 공급자·로그 형식별 usage 의미와 중복 제거 키를 명시한다. Claude 메시지 로그는 해당 run 범위의 `message.id`, provider 응답은 그 형식의 요청/응답 ID를 확인한다. 서로 다른 요청을 내용이 같다는 이유로 합치지 않는다.
- 같은 ID의 동일 usage는 한 번만 센다. 같은 ID의 usage가 달라지면 스트리밍 중간값·최종값·누계 의미를 확인한다. 근거 없이 첫 값·마지막 값·최댓값을 선택하거나 모두 더하지 않는다.
- 세션 누계와 요청별 증분을 섞어 합산하지 않는다. 서브에이전트·재시도·복구 호출의 포함 범위를 명시하고 원자료에 없는 비용을 확정하지 않는다.
- usage 누락은 **미측정**으로 표시하여 0과 구분한다. 캐시 필드가 없다는 이유만으로 캐시 미지원이라고 단정하지 않는다. 비용 집계가 불가능하면 비용 판정만 제한한다.
- 비캐시 입력·캐시 읽기·캐시 쓰기·출력·reasoning 포함 관계를 구분한다. 출력에 포함된 reasoning을 다시 가산하지 않는다. 토큰 수만으로 다른 모델의 비용 우위를 주장하지 않는다.
- `input + output + cache_creation`은 **토큰 대리지표**로 표기한다. 실제 비용은 확인한 청구 의미·당시 단가·캐시 정책으로 계산하고 단가 출처/시점을 남긴다. 구독 지출과 API 단가 환산 추정치는 구분한다.
- 집계기 버전·명령, 원자료 경로·포함 범위, 고유 요청 수·중복 수·누락 수를 보고한다. 집계기를 수정할 때 실제 오류를 재현하는 중복·누계·누락 처리 회귀 검증을 수행한다.

## 5. 판정·보고 — 관측 범위를 넘지 않기

- 사전 기준과 관측값을 대조한다. 30% 절감에 미달했는데 “30% 이상 절감 검증”으로 기록하지 않는다. 수치 정정 시 판정도 재검토한다.
- **3/3 성공**은 해당 조건의 관측값이다. “재현성 확정”이나 일반적인 높은 성공률의 증명으로 표현하지 않는다. 비율에는 표본 수와 적절한 불확실성을 제시하고 독립성·과제 범위의 한계를 적는다.
- 관측 범위의 겹침은 동등성의 증명이 아니며, 비겹침은 원인의 확정이 아니다. 동등성 주장은 사전 허용 차이와 적절한 분석이 필요하다. 설명 가설과 직접 검증한 사실을 구분한다.
- 실무 효율은 동일 품질 기준 아래 **예산 내 합격률·비용·시간**으로 평가한다. 사람 개입 트랙은 검토·수정 시간도 포함한다. 무개입 결과를 사람의 생산성 개선으로 바로 일반화하지 않는다.
- 실패·재시도·복구를 전체 비용과 시간에 포함한다. 성공 run만의 비용·시간은 조건부 지표로 명시하고 실패율을 함께 제시한다. `전체 관측 비용 / 합격 건수`는 합격 0건이면 유한 값으로 보고하지 않는다.
- 사전 규칙에 따른 장애 제외 분석을 제공하더라도 실무 조합 비교에는 장애 포함 전체 결과를 함께 보고한다. 같은 과제의 반복 run을 독립적인 여러 과제로 세지 않는다.
- 정정 시 이전 값·정정 값·이유·영향받은 결론을 남긴다. [CLAUDE.md](../CLAUDE.md)의 결과 동기화 절차에 따라 보고서, 카탈로그, ROADMAP, 다국어 README와 대시보드의 관련 내용을 맞춘다.
